# P13 — the design round, built

P12 shipped the design work the second testing round asked for and left a brainstorm behind it.
That brainstorm became a decision sheet of fourteen questions — each with a rendered
illustration, each carrying a recommendation — and the maker answered all fourteen.

**Seven said build it. Seven said leave it out.** Both halves are in this milestone: the
refusals are written into CORE §6 so the next brainstorm cannot quietly reopen them, which is
the same reason P12 spent its first stage making CORE true before changing it.

| | Decision | Answer |
| --- | --- | --- |
| D1 | Icons at all? | Yes — adopt icons |
| D2 | Which family? | **Font Awesome** |
| D3 | How far do icons go? | Status bar + sidebar now |
| D4 | Three rows or one line? | **Keep three rows** |
| D5 | How progress is shown | Track → the bar's top edge |
| D6 | Long paths | Middle truncation, full path on hover |
| D7 | Clickable path | Yes — opens its folder |
| D8–D14 | Second typeface · emoji · OS blur · animation · green flash · muted yellow · 3px strip | All left out |

## Two answers went against the recommendation, and both were right

**D2 chose Font Awesome where the sheet recommended Material.** The sheet's own tiebreaker said
the choice only turns on set size *if* icons reach the entry table, and named Font Awesome's
archive drawer as the better glyph otherwise. D3 stopped short of the table. The maker followed
the argument to its conclusion rather than the recommendation at the top of it.

**D4 kept three rows.** The sheet recommended one line and was wrong, which an adversarial pass
against the source had already found before publishing: `Cancel` lives in row 3 and is the only
user-reachable writer to `app.cancel` in the program, so a collapse makes long work
uninterruptible. Merging rows 2 and 3 would also have re-created the bug P7 shipped and fixed —
status text hidden behind `progress.is_some()`, so every refusal fired at exactly the moment it
could not be seen. The saving was 48px, not the 70 first claimed.

## What was built

**Icons.** `theme::icon` names nine glyphs by **role, never by codepoint**, so no call site holds
a hex escape. They cost no asset: the Nerd Font already in the binary carries 9,260 of them, and
CORE §6 now says icons are glyphs of the same face, which is what keeps *"one typeface,
monospace, everywhere"* literally true rather than nearly true. Two tests hold it —
`every_icon_exists_in_both_faces` walks the embedded `cmap` in a hand-rolled parser and fails the
build on a glyph that would draw as tofu, and `no_two_icons_are_the_same_glyph` catches the
copy-paste slip that reads as a deliberate choice on screen.

**Twice the size, and the bar grew to carry it.** The maker's verdict on the first cut was
*"icons only sensible when they are big enough"*, and the fix had a cost worth recording:
`SB_ROW` had to rise from 20 to 32, which meant splitting **`CONTROL_H`** away from it. They had
been the same number for eleven milestones, and the coupling read as economy — but "a button is
a row tall" would have made every button in the program 32 tall and turned `R_PILL`'s 10 into a
merely rounded corner, which is the one shape CORE §6 refuses. `SB_HEIGHT` went 100 → 136.

**The path.** `util::elide_middle` counts `chars` and never bytes, because the corpus this
program is tested against is Turkish and a byte-slicing version panics on the first `ş`. The
column budget is measured from the font at the size the row actually uses — arithmetic that is
only true because the face is monospace, noted at the call site rather than guarded. Clicking
the path hands the folder to `xdg-desktop-portal`, which cost a feature flag and no crate:
`open_uri = []` upstream, so `check-deps.sh` reads identically before and after.

**Progress on the edge.** The track left row 3 for a 2px line along the panel's own top edge —
painted, never allocated, because `exact_size` means the panel cannot grow to absorb a widget.
Orange already meant progress and 2px was already the edge weight, so the change cost the
document no new vocabulary at all.

## Deviations

1. **The sidebar's *Archive* row takes the archive drawer, not the folder the mockup showed.**
   Put to the maker in planning and chosen deliberately: one glyph, one meaning, in the sidebar
   and the status bar alike.
2. **A warning glyph precedes a failure**, which is redundant with the colour on purpose — CORE
   §6 now carries the exception in writing, because colour alone carrying meaning fails anyone
   who cannot separate `#FFD800` from grey.
3. **The cursor ring was wrong, and P12 put it there.** `TableRow::response` spans the whole line
   including the gutter the scrollbar reserves, but `egui_extras` paints its row fills *per cell*
   — so the ring drew a box wider than the wash beneath it, and the overhang read as an empty
   fifth column. Reported as *"this place look weird"*, and it was. The ring now follows the
   union of the first and last cells, which is what is actually painted.
4. **An afternoon went into an adaptive sidebar header, and all of it was rolled back.**
   The report was that the two list sections scrolled out of view. The cause was real —
   `with_min_inner_size` is a request KWin declines, and it hands INDIUM 960×540 whatever
   floor is named — but every fix attempted on top of it was worse than the problem. In order:
   commanding the window back up to its floor (granted for one frame, then revoked, and it
   fought the hand resizing the window); shrinking the mark as the zone tightened (*"app logo
   dead"* — a photograph at twenty-four points reads as damage); dropping the mark entirely
   (correct on paper, and it hid the logo from every window this machine actually produces);
   and moving it beside the wordmark (which fixed the logo and introduced a header that
   relayouted on a one-pixel drag: *"very different look"*). The maker called it, and the call
   was right: **the header is fixed and does not adapt.** If the window is too short for it,
   the sidebar scrolls, exactly as it did before any of this and exactly as every other
   program behaves. What survived is the padding trim — 45 points of it — which is why the
   sidebar fits in more windows than it used to without anything moving.

5. **Points are not pixels, and an afternoon went into relearning it.** Chasing the sidebar,
   a screenshot and the program disagreed about the window: the capture said 1200×675, the
   program said 960×540. Both were right. This display runs at a scale of **1.25**, and every
   ratio in the session is exactly that — 1200/960, 675/540, and the 850 measured in the one
   frame the floor held against its 680. Believing the capture produced a diagnosis that was
   confidently wrong ("the mark disappeared from a window with room to spare"), and the
   comments asserting it were removed rather than left to be quoted later. Nothing else in
   this milestone is affected: CORE's line weights, the window floors and the window
   floors are all in points and always were.
6. **Two window floors, named and left as requests.** 900 wide is the three zones' own
   minima — sidebar 202, Inspector 272, and a table that needs 384 for four columns once
   `egui_extras`' column spacing is counted, plus its scrollbar, over 20 of central chrome.
   It read 880 until an audit found the spacing missing from the sum, which had put the
   floor below its own arithmetic. 680 tall is a height the sidebar fits inside with slack.
   Neither is enforced beyond asking, and this compositor does not grant either.

7. **`R_CTRL` survives without the progress track.** It still dresses text fields and checkboxes,
   so `only_three_corner_radii_exist` is untouched; the constant's own doc now says what left.

## What P13 deliberately did not do

- **Per-file-type icons in the entry table.** D3 stopped at the bar and the sidebar; the table is
  virtualised and hundred-row, and deserves its own round.
- **The one-line bar.** If the space is ever wanted, merging rows 1 and 2 is the version that
  touches neither `Cancel` nor P7's lane rule.
- **`tasks::lock_name_for`**, which still folds every non-ASCII character to `%`, so `açık.zip`
  and `aşık.zip` share a lock. Recorded since P11, still unfixed, still low severity.
