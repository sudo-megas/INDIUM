# P18 — the record round

*`v1.2.0-2`. The date the About popup has been printing since three tags ago, four screenshots
of a program that no longer exists, a sentence in CORE that says CI has not arrived yet, and a
comment claiming a test does something the test cannot do.*

## Why this round

P16 and P17 were both chosen by the same rule: *a promise printed by the program is a debt.*
P16 found the Inspector promising hex in V1.1; P17 found `USAGE` promising headless subcommands
in V1.3, and called it the last live one.

**It was.** A sweep of the whole tree found no `TODO`, no `FIXME`, no `todo!`, no
`unimplemented!`, not one `#[allow(…)]`; every one of the fourteen rows in `keys.rs::ROWS` bound
to a live handler; all nine `Popup` variants reachable; no `.clicked()` result discarded. The
rule that chose the last two rounds is **exhausted, for the first time in the project's
history**, and P17's claim about itself holds.

So the round was chosen by the other rule instead — *a false sentence in the record costs more
than the defect it covers* — and by the one class P17 named as never yet beaten:

> **Every number in this project a test can reach has been right for sixteen milestones.**
> This is the class that has not.

That class is *claims nothing can check*. Its history is a straight line. The README's size
badge, wrong for three releases, found in P15. The `.deb`'s font attribution, wrong for three
releases, found in P17 — and in the same file, DEP-5 separators missing for ten. Every one of
them found by a person looking, never by a gate.

Seven more were live when this round opened, and two of them are the front door.

**About prints a date from three tags ago.** `RELEASE_DATE` is drawn beside
`env!("CARGO_PKG_VERSION")`, so the binary published as v1.2 opens its About popup and says
**Version 1.2.0 · Date 2026-08-10**. The tag is dated the 11th. The constant was last touched in
the `v1.0.0-4` bump and has been skipped by `v1.0.0-5`, `v1.1` and `v1.2` — while the comment
directly above it reads *"Updated by the maker at each tag, by hand, in the same commit as the
version bump."* Nothing in `tests/` or `build/` so much as names it.

**The README's four screenshots photograph a program that no longer exists.** They were last
retaken in P8. Since then P9 rebuilt the popup grounds, P12 changed the typeface to Fira Mono and
reordered the sidebar and made every control a capsule and gave the status bar a hierarchy, P13
put nine icons into the sidebar and the bar and moved progress onto the bar's own edge, and P16
added the hex view. **Three of the four shots are popups** — New Archive, Extract and About,
exactly the surface P9 rebuilt. P7 opened a box for this once, in words that still apply: *"the
whole visual language changed; four pictures of the old one on the front page would be P6's own
unforgivable failure, in image form."* P8 retook them. Four rounds re-opened it in silence, and
`P6.md`'s *"the README describes a program that exists"* went quietly false.

Four more are the record itself. `CORE.md` §2 and `check-deps.sh` both still say V1.4 *will* wire
`check-deps.sh` into CI — P15 shipped exactly that — and **`ci.yml` quotes the stale sentence as
its own justification**, which is the twin-sentence defect at its most vivid: the round that paid
the promise cited it instead of retiring it. §3's module table names seven modules where `src/`
has ten, and the missing one that stings is `secret`, because §3's own closing paragraph
describes password zeroing as a property of the architecture and the module that implements it
has no row. §7's tag rule opens *"Tags are two-numeral: `v0.1`, `v0.2`, …"* and **`v0.1` has
never existed**, on this machine or on origin. §6 says *"Six grounds in aubergine"* and lists
five.

And one of the false claims is a test. `tasks.rs` says the method verdicts are *"pinned by a
test, so a future edit to CORE cannot drift away from the window without someone noticing."* The
test compares `Method::verdict()` against a second hand-copy of the same sentences **in the same
file**. Editing CORE §5 leaves `cargo test` green. The comment describes a gate that does not
exist.

**Then planning this round measured something nobody had measured.** `TEXT_MUTED` on `AUBERGINE`
is **3.30:1** — under the AA floor this project's own tests assert everywhere else. The test named
`text_is_legible_on_every_ground` never saw it, because `AUBERGINE` is not in `GROUNDS` — though
the test directly below it chains `AUBERGINE` in by hand and calls it *"the lightest ground any
line in this program meets and therefore the worst case."* Aubergine is
`widgets.hovered.bg_fill` everywhere, and `selection.bg_fill` inside `active_fill`'s scope. Muted
ink is painted on it in five places, on every row a person has just selected or is pointing at.
*(This sentence read "Aubergine is `selection.bg_fill`" flatly until the sweep; that half is true
only in that one scope, and believing it globally is why the entry table went unexamined for most
of the round. See the sweep below.)*

## What makes this a round and not a tidy-up

Correcting a sentence is worth little; the sentence was correct once and went stale, and the next
one will too. What this round is actually for is the second half: **every claim it fixes is
pinned to the document or the artefact it describes**, so the drift cannot happen twice.

The technique was already here, in one place, written by P12 and used by nothing else —
`keys.rs`, whose test reads `CORE.md` itself rather than a fixture, and whose doc comment states
this round's whole argument two rounds before the round:

> It reads the document rather than a fixture, so an edit to CORE §4 that forgets this popup
> fails here — which is **the direction drift actually travels: the document moves first in this
> project, and the code follows.**

P17 reached the same idea from the other end when its packaging gate stopped counting licence
files and started reading the attribution. This round makes it the rule.

## Deviations

1. **The fourth reader was replaced by primary-source verification.** The plan said every finding
   would be put to a reader told to refute it. Instead each was checked directly against the file,
   the release body or a measurement. That is stronger evidence, not weaker — and it is the reason
   one of the sweep's headline findings was rejected, see 2 — but it is a departure from what was
   written down, and this project records those.
2. **A sweep finding was wrong and had to be re-measured.** The reader that found the selection
   ground also reported muted ink there at 2.1–2.6:1, *"worse than the 3.30:1 the whole round was
   written to fix."* It is 3.72:1: the figures quoted were `AUBERGINE_LIT`'s, one row up in the
   reader's own table. The defect is real and the fix stands; the severity was not. **A finding is
   evidence to check, not a verdict to copy** — the same standard this round applied to everything
   else it was told.
3. **D5's scope grew from five call sites to eight.** The three added are the entry table's, found
   after the ruling. No design decision was taken: the wash is untouched, and the ink steps up one
   tier exactly as it does at the five. Changing the wash would have been §6's business and the
   maker's, and is not proposed here.
4. **The round is more commits than the fifteen planned.** The sweep's findings needed two of
   their own, which is what P16 did, and the ritual then needed several more — see Deviation 6. The
   figure is deliberately not written down: `git log 4f76af9..v1.2.0-2` counts it exactly, and any
   number put here is one the next commit falsifies. This document said *"seventeen"* until the
   ritual made that wrong, which is the third time this round a count outlived what it counted.
5. **The four README screenshots were not retaken, and this document named them as one of the
   round's own live false claims.** Retaking them needs the program running in a compositor with a
   person at it; it cannot be done from the terminal this round was built in. It is left open and
   ticket-shaped below rather than quietly dropped — but it means P18 ships having corrected the
   record everywhere except the one place it opened with. **That is the round's largest gap and it
   is the maker's to close.**
6. **The ritual found two more, which is the round's own subject arriving late.** Neither is a
   defect the round introduced; both are claims that only a release could falsify, and the release
   is what found them.
   - **CORE §7 said *"Four release bodies carry that sentence"*.** True when written — checked
     against all five published bodies, and `v1.0.0-3` genuinely does not carry it. It stops being
     true the moment this release is published carrying it. That is §2's defect at a distance of
     350 lines: §2 deleted its own count this round *because a number describing a list kept
     elsewhere goes stale when the list grows*, and §6 recreated it 70 lines from that fix. This
     third one would have been falsified by the act of shipping. The count is gone; the rule now
     states why it carries none.
   - **The README named the `1.2.0-1` artefacts in five places**, so the front page frozen at the
     tag would have sent a new reader to the superseded revision — which does not 404, because the
     `-1` files are still on the `v1.2` page. Nothing reads `README.md` from a test, and the
     ritual step meant to catch it named only the badges and the screenshots. Corrected in §3, and
     the step now names the filenames.

   **Both were found by checking a claim at its source before acting on it**, which is the one
   habit this round was written to install. The record round's own record needed the same
   treatment on the day it shipped.
