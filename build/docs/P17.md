# P17 — the terminal half

*V1.2. The last promise the program printed, a panic that had been in every shipped binary
since P1, and a copyright file that had been contradicting itself in adjacent paragraphs
for four releases.*

## Why this round

P16 chose the hex view over the icons round on one argument: `inspector.rs` printed a
sentence promising hex in V1.1, and *"a promise printed in the window is a debt."* The same
test was applied here, and `src/main.rs` answered it — inside the `USAGE` const that
`indium --help` has printed since P6:

> `Headless subcommands (extract, list, single-file open) arrive in V1.3.`

A sweep of `src/` found it to be **the last live one**. There is no `TODO`, `FIXME`,
`todo!` or `unimplemented!` anywhere in the tree; `util.rs`'s note about hex is historical
and says so; `tasks.rs`'s method verdicts point at V2.0's estimator, which is not due; and
`sidebar.rs`'s *"is not available yet"* arm has been unreachable since P4.

**The icons round is still nominated and still undecided, and nothing here forecloses it.**
No glyph was added, `theme::icon::ALL` is untouched, `ROW_HEIGHT` is still 20. When it is
taken up it begins with a §6 ruling, exactly as P16 left it.

## The decisions

Put to the maker as a sheet, in the manner of P13's fourteen. Four questions, four answers.

| | Question | Ruling |
| --- | --- | --- |
| D1 | `clap`, or `std::env::args`? | **No `clap`** — record the refusal, dated |
| D2 | `args()` panics on non-UTF-8 argv | **Fix it in this round** — `args_os()` |
| D3 | What version and tag? | **`v1.2`, and renumber the roadmap** |
| D4 | Encrypted archives, headlessly | **Prompt on `/dev/tty`, echo off** |

**D3 went against the recommendation**, which was to skip to `v1.3` and leave `v1.2`
standing for the yazi plugin. The maker's reasoning is the better one and is now §7's: the
plugin is *"versioned separately"* and can therefore never take an INDIUM tag, so `v1.2`
was not a slot anything would ever fill — and a hole in the tag sequence for a thing that
will never arrive is worse than a renumber. The cost is real and is written into §7 rather
than hidden: **five published releases print *"arrive in V1.3"*** for a thing that arrived
at `v1.2`, and those tarballs cannot be edited.

## What was built

**`src/cli.rs`** — in the library half, for the reason `lib.rs` already gives. `run` returns
an exit code and writes through `dyn Write` instead of calling `process::exit` and
`println!`, which is the whole reason `tests/cli_path.rs` can drive all sixteen of its cases
inside the test process rather than by spawning one.

The surface is `list`, `extract`, `cat`, entered only when the first argument is
**byte-exactly** one of those words. `./list` and `listing.zip` are archives; `USAGE` says
so, because it is the one ambiguity in the whole thing.

- **`list`** prints one stored path per line, undecorated, in archive order — **no trailing
  slash on a directory**, because that output is an input to `cat` and `extract`, and a
  decorated name is not a name. `-0` separates with NUL: an archive may hold a member whose
  name contains a newline, and a line-oriented listing of one is silently wrong. `--long`
  is declared *in `USAGE` itself* to be for a person and not for a script, which is what
  makes its aligned columns honest rather than a trap; every column comes from the function
  the window already uses, so the two halves cannot come to describe one archive differently.
- **`extract`** with no member named takes everything, and that sentence is written around a
  real trap — see below.
- **`cat`** streams through `arch::stream_entry`, uncapped.

**`arch::stream_entry`** — the uncapped read `cat` is built on, sited beside `head_of` and
routed identically. `head_of` caps at 8 MiB so the Preview cannot make the window disappear;
a `cat` that stopped there would be the same class of lie, and calling `head_of` with
`usize::MAX` is not the fix either, because it does `take(cap as u64 + 1)` and overflows.
It copies through `EntryData`, already the rebuild path's `io::Read`, so short reads and
sparse holes are not handled a second time — and going through `Reader::open` is what gives
it the RAR gate and P11's locale fix for free.

**`std::env::args_os`** — `args()` panics on an argument that is not valid Unicode. Proven
rather than argued: the old idiom exits **101** with `called Result::unwrap() on an Err
value: "/tmp/caf\xE9.zip"`, and the same argument now reaches the ordinary *does not exist*
and exits 1. It had been in every shipped binary since P1. Nobody hit it because the corpus
INDIUM is tested against is Turkish in UTF-8 — luck, not a design.

**The password prompt.** `/dev/tty`, not stdin and not stdout, and both reasons are real:
`indium cat a.7z x > out.bin` has stdout as the data channel, so a prompt written there
would land inside the file; and anything in a pipeline must not have its prompt eaten by
whatever is feeding stdin. Termios by hand, as `arch.rs`'s `setlocale` block already is —
every number printed by a C program compiled against the installed headers rather than
counted by eye, which is what `arch.rs` did for `CODESET`: `sizeof(struct termios)=60`,
`NCCS=32`, `ECHO=010`, `TCSAFLUSH=2`. The size is asserted at compile time as well.

Only `ECHO` is cleared — `ICANON` stays on, so the line can be edited and ends at Enter,
which is what `getpass` has always done. A restore-on-drop guard puts the terminal back
however the scope is left. **With no controlling terminal it refuses and exits rather than
blocking**, which is the branch a cron job or a CI runner reaches.

## The trap `extract` is written around

`arch::selection_matches` returns **false for an empty set**. So the obvious implementation
of *"no member named means everything"* — pass an empty `wanted` and let `arch::extract`
sort it out — writes nothing at all, returns `Ok(0)`, and reports a clean success. The exit
code is the part that lies, which is why `an_extraction_with_no_member_takes_everything`
asserts on the files on disk and not on the code. The CLI lists first and names every entry
explicitly. `arch::extract`'s own semantics are untouched: the window depends on them.

## The record, straightened

**The `.deb` has been misattributing the embedded font since `v1.0.0-4`.** P12 (`889c207`)
swapped the face to Fira Mono Nerd Font Mono and did not bring
`build/package/deb/copyright.header` along, so its DEP-5 stanza has read `Copyright: 2020
The JetBrains Mono Project Authors` ever since. `make-deb.sh` builds
`/usr/share/doc/indium/copyright` by concatenating that header with
`LICENSES/OFL-1.1.txt`, whose first line reads *"Digitized data copyright (c) 2012-2015,
The Mozilla Foundation and Telefonica S.A."* — so **every published `.deb` for four
releases has carried a copyright file naming two different holders for one font, in
adjacent paragraphs.** The Arch package is unaffected; it installs the OFL text verbatim
and so cannot disagree with itself.

Checks 5 and 7 of `verify.sh` count licence *files* and control *fields*. Neither reads a
word of attribution, which is exactly why this had to be found by a person — the same shape
as the README size badge P15 caught. **Every number in this project a test can reach has
been right for sixteen milestones.** This is the class that has not.

**And a second defect in the same file, found while fixing the first.**
`LICENSES/OFL-1.1.txt` is **CRLF in all 93 of its lines** — it is copied verbatim out of
the font package, and that is how the OFL ships. `make-deb.sh`'s `sed 's/^$/./'` therefore
matched *nothing*: eighteen lines that read as blank each hold a lone carriage return, so
every one of them was emitted as `` ` \r` `` instead of `` ` .` ``. The comment above that
recipe has described eighteen DEP-5 separators that were never once produced, since P6.
Counted rather than assumed: the old recipe emits **zero**, the new one emits **eighteen**,
and no carriage return survives into the package. It parsed either way — a space followed
by CR is still a continuation line — which is why nobody saw it.

The CRLF also very nearly defeated the check written to catch the first defect: the derived
holder and the typed holder printed identically and compared unequal, on an invisible byte.
The plan for this round had predicted the trap would be the accent in *Telefónica* versus
*Telefonica*. It was not; it was a carriage return, and only a byte dump found it.

## The sweep, which was a step again

P16 made the sweep a step and it caught that round; the same discipline is applied here,
and the things it turned up are recorded rather than quietly fixed.

**Three defects were found by running the program rather than by reading it**, which is
worth naming as a class, because reading had not found any of them:

1. **The password retry has to include `WrongPassword`, not only `NeedPassword`.** Which
   error comes back depends on *where* the refusal happened, not on what the user did:
   `extract` decides in its pre-flight that a selected entry is encrypted and says
   `NeedPassword`, while `stream_entry` only finds out when libarchive is asked for the
   bytes, which surfaces as a passphrase failure. So `cat` of an encrypted member **with no
   password at all** came back `WrongPassword`, and the prompt never fired. The window has
   always treated the pair together at `ui/mod.rs:798`; the terminal half now does the same
   rather than inventing a second rule.
2. **The counts were not pluralised.** *"Extracted 1 entries."* beside the window's
   *"Extracted 1 entry."* — two vocabularies for one program, which is the precise thing
   this module was written to avoid, appearing in its first hour.
3. **`TCSAFLUSH` discarded a test's own input**, which looked like a bug and is the flag
   doing its job: a password typed ahead of the prompt is thrown away rather than echoed by
   the old settings and then read. The test harness was wrong, not the code.

**Two behaviours were mutation-tested rather than trusted**, in the manner P16 closed its
round with:

- Handing `arch::extract` an empty selection when no member is named — the run still exits
  **0**, and the suite failed at *"alpha.txt was not extracted"*.
- Matching the subcommand by prefix instead of byte-exactly — the suite failed on
  `listing.zip`, at *"a prefix match would take this"*.

## Deviations

1. **The 7z branch of `stream_entry` does not stream.** `sevenz::read_entry` reads the
   member into a `Vec` before a byte reaches the output, so `cat` of a four-gigabyte 7z
   member wants four gigabytes of memory where the libarchive branch wants none. It is not
   a new compromise — `extract` and `crc32_of` already do this for 7z, because
   `sevenz-rust2` decodes a solid block at a time and there is no smaller unit to hand out.
   `usize::MAX` was *checked* rather than assumed safe there: that function uses
   `take(cap as u64)` with no `+ 1`, so nothing overflows.
2. **`cat` does not refuse to write binary to a terminal.** `cat(1)` does not either, and
   the name is the promise. Recorded rather than fixed, because a terminal check now exists
   in this module for the password prompt and somebody would otherwise propose reusing it
   here as a discovery.
3. **Ctrl-C during the password prompt leaves the echo off** until `stty sane`. The
   restore-on-drop guard covers a panic; a signal skips it. The fix is a `sigaction`
   handler installed for the prompt's duration — `tcsetattr` is on POSIX's
   async-signal-safe list, so it is legitimate — but **this project installs no signal
   handler anywhere**, and installing the first one is a ruling and not a detail.
4. **A 7z listing does not reach `ensure_ctype_locale`.** Every other terminal path goes
   through `Reader::open`, where the guard lives; a 7z routes through `sevenz::list_all`
   and never touches libarchive. Harmless — 7z names are UTF-16, decoded in Rust, not
   converted through the C locale — but stated here so a sweep does not file it as a hole.
5. **The four CORE operations landed in the `v1.2` commit rather than in the documentation
   commit**, because the version bump's `git add -A` swept them in. The commit message
   names only the §7 swap, so the §2 and §3 edits are recorded here instead of there. Not
   worth rewriting history over; worth not pretending about.
6. **`cat_does_not_stop_where_the_preview_stops` lives in `read_path.rs`, not
   `cli_path.rs`** where the plan put it. It tests `stream_entry` directly, which is the
   true unit — a nine-megabyte member is built rather than taken, because every committed
   fixture is kilobytes and a `cat` wrongly built on `head_of` would pass against all of
   them.

## The CORE operations

Five. None touches §9.

1. **§2** — the `clap` conditional is spent, and becomes a **dated refusal** with its
   reasoning, in the shape of §6's seven: three subcommands, one string option and two
   flags is forty lines of `match`, its sentence would read *"parses six flags"*, and the
   derive path would bring a colour-negotiation stack to a program with one palette.
2. **§2** — *"argument handling is `std::env::args`"* becomes **`std::env::args_os`**, with
   the reason.
3. **§3** — a `cli` row in the module table, saying that it opens no window and touches
   nothing in `ui`, and why that second clause is there.
4. **§7 road table** — a P17 row, at **`v1.2`**.
5. **§7 *After v1.0*** — **headless becomes V1.2** and records that it shipped here; **the
   yazi plugin becomes V1.3**, keeping its conditional wording; the swap and its cost are
   written down; and the PDF paragraph's cross-reference, which read *"It joins **V1.2's
   plugin**"*, now names the plugin instead of numbering it — **a cross-reference by number
   could not have survived a renumber**, and it sat one line above the lines being edited.
   That is the twin-sentence shape P16 committed while writing about it, caught this time
   because the plan named it in advance.

**Deliberately not done.** The *"Not in P&lt;n&gt;"* lines in `P6.md`, `P7.md` and `P8.md`
say *"headless subcommands (V1.3)"* and are **left exactly as written**. They were true
when written; the renumber is a change to the road, not a false claim about the code, and
§7 is where the road is recorded. This is the opposite treatment from P15's and P16's
corrections, and the distinction is the point: those documents said something untrue about
the program, and these do not.

## Two boxes the record left standing

- **`P16.md`'s *"Released as `v1.1`"* is ticked here.** It could not have been ticked in
  P16: that document was committed at `fd5073a`, which *is* the tagged commit, so the
  release came afterwards. Verified before ticking — `gh release view v1.1` shows three
  artefacts, published and marked Latest, with both workflow runs green.
- **`P10.md`'s CORE-edit box is the one box in the whole ledger that reads as unresolved by
  omission rather than by design.** P9's equivalent carries a retroactive *"(ticked in
  P15…)"* note; P10's never received one, though P12's *"eighteen operations… applied"*
  almost certainly resolves it in substance. Left for the maker's eye rather than ticked by
  this document, because a box ticked by somebody who was guessing is worse than one left
  open.

## P17 is done when

- [x] `indium --help` no longer promises anything it does not do.
- [x] `list`, `extract` and `cat` work, and open no window on a machine with no compositor.
- [x] `cat` does not stop where the Preview stops — held by a test that builds its own
      oversized member, because no fixture could catch it.
- [x] An empty selection cannot silently extract nothing — held by a test that asserts on
      files, because the exit code is the part that lies.
- [x] An encrypted archive is asked on `/dev/tty` with the echo off, and refuses rather
      than hangs when there is no terminal — held by a test that spawns `setsid`.
- [x] A path that is not valid Unicode no longer aborts the program.
- [x] The `.deb` names the font it actually embeds, and a check reads the attribution
      rather than counting the files — seen failing before it was believed.
- [x] No new dependency. `clap` refused, with a date on it.
- [ ] Checked at the window, by a person, at both 125% and 100%.
- [ ] Released as `v1.2`.

The first of those two is the maker's, and it is left standing open for the reason P12
taught: a box that belongs to nobody is a box that stays empty long after the thing it asks
for has happened. **The window was not changed by this round at all** — no zone, no popup,
no key — so what it asks for is a confirmation that nothing moved.

## The ritual

CORE §8. **A version and not a revision**, which changes three steps:

1. `cargo fmt --check` · `cargo clippy --all-targets -- -D warnings` · `cargo test` ·
   `cargo build --release` · `./build/check-deps.sh`, all five by hand, all five again
   in CI.
2. **`Cargo.toml` is `1.2.0` and `pkgrel` stays `1`.** Those two together are what make the
   tag two-numeral: `release.yml` derives `if [ "$REL" = 1 ]; then EXPECT="v${VER%.*}"`, so
   the only tag it will accept is **`v1.2`**. Checked by running that derivation against
   the tree rather than by reading it.
3. `changelog.Debian` gains a stanza whose first line is exactly
   `indium (1.2.0-1) unstable; urgency=medium`, the string `verify.sh` check 9 asserts.
4. `README.md`: the badges, the six artefact filenames, the two install commands, and a new
   *Without the window* section — the program grew a second face and the front page had
   only ever described the window. The Debian size badge is re-measured off the artefact
   this tag actually publishes, which is the defect `a08cd93` closed and P15 recorded.
5. Commits in the house voice, from **sudo-megas**, with no AI attribution anywhere.
6. Push. `ci.yml` green on that push. Then `gh workflow run release` — the dispatch before
   the tag, because packaging is never proven on this machine: the committed PKGBUILD pins
   its own `source=` fragment and only the workflow rewrites it.
7. Dispatch green → tag `v1.2` → tag run green → download its three artefacts →
   `gh release create v1.2`, titled **"INDIUM 1.2 — the terminal half"**, notes in the
   house voice. The *"Still a beta"* line stays: the gate for dropping it is a testing
   round in real hands, and that has still not happened.
