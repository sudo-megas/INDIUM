# P19 — the front page, read against the tree

## Why this round

P18 shipped as `v1.2.0-2` and closed the record round. Then the maker reworked the README's
header on GitHub — a centred mark, a Display Server badge, an Arch size badge, the Debian badge
re-measured, a new tagline — and asked for the front page to be read end to end against what the
program actually is.

**P18's thesis was claims nothing can check. `README.md` is the largest one in the project.** No
test reads it: the only greps that land on a README point at `tests/fixtures/README.md` and
`assets/fonts/README.md`. A front-page edit made in a browser lands with no gate behind it at
all, and the front page is what a person reads before anything else.

The read found five things the tree contradicts. **Two of them are not README defects.** They are
defects in the governing document that the README, and the packages, and in one case a shipped
artefact, faithfully copied.

### The library that three of four packages never declared

`CORE.md` §2's system-library row named `libwayland-client`, `libxkbcommon` and `libEGL`. The
binary opens **four**: `libwayland-egl.so.1` as well. All four are `dlopen`ed by soname, so they
appear in no `ldd` output and no shlibs machinery can find them — `make-deb.sh` says exactly that
where it declares them, and says why it must name them by hand: *"because CORE §2 names them, and
a package that omits them fails at the first window rather than at install time."*

Named by hand, from a row that was short one. The omission then went:

| Site | Named it? | Effect |
| --- | --- | --- |
| `PKGBUILD`'s comment | **yes** | correct throughout, and moot: one `wayland` package carries both sonames |
| `CORE.md` §2 | no | the source everything else was written from |
| `README.md` §3.C | no | a tarball user told to satisfy three of four |
| `make-deb.sh`'s `Depends` | no | **`libwayland-egl1` is a separate package on Debian** |

**Measured on the published artefacts, not on a local build.** The `.deb` downloaded from the
`v1.2.0-2` release page contains a binary that opens `libwayland-egl.so.1`, and that same `.deb`
declares `libwayland-client0, libxkbcommon0, libegl1` and not `libwayland-egl1`. The binary that
shipped needs it; the package that shipped it does not declare it.

Latent rather than routine — any machine running a Wayland session already has the library, pulled
in by its compositor or by Mesa. But it is a declared-dependency gap in a project whose stated
standard is that these are named by hand *precisely because* nothing automatic can find them.

### The panel's third group, and the destructive control no document had

`CORE.md` §4's popup 5 read *"One small panel: bookmarks, default extract behaviour."* The panel
has drawn **three** groups since P2 — Extract, Bookmarks, Recent files — and the third carries a
**Clear list** button that empties `recents.toml`. README §4 enumerated the same two CORE did.

A destructive control existed in the window, in `settings.rs`, and in that file's own header, and
in no governing document.

**The count was not lost, it was misfiled.** `settings.rs` opened by quoting *"Exactly three
groups, nothing else, and no room grows later without a CORE edit: Extract, Bookmarks, Recent
files"* — P2's sentence, correct about this file for seventeen rounds — and attributed it to
**CORE §4.5**, a subsection number CORE has not had since §4 was reorganised. The one place
carrying the right answer pointed at a section that could not confirm it.

### Three smaller ones

- **README §2's Arch build list** said *"`sudo pacman -S libarchive rust`. That is the whole
  list."* `PKGBUILD` declares `makedepends=('git' 'rust')` and its `source=` is a `git+` URL;
  §3.D's own instructions open with `git clone`. A closed claim with three entries. It survived
  because anyone following §3.D already had `git` in hand.
- **The Inspector showed no ratio for a single entry.** The aggregate card and the whole-archive
  card have both stated one since P1; the single-entry card — the one a person reaches first —
  printed Size and Packed and left the division to the reader, while README §1 listed ratio among
  what the Inspector states about a selection.
- **`--long` prints a column neither the help nor the front page named.** The row carries mode,
  size, packed, method, encryption, time and the member **path**; the help listed six of seven and
  the README quoted the help verbatim, so program and front page agreed with each other and both
  under-described the output by the one column a listing exists for.

### And the two P18 nominated

Taken up by the maker's ruling rather than deferred again:

- **`sevenz.rs`'s `Err(_) => Password::empty()`** — a password whose bytes are not valid UTF-8
  became *no password*, so the operation returned "Wrong password." **The path is reachable, not
  theoretical**: `cli.rs` reads the terminal password as bytes off `/dev/tty` and builds
  `Secret::new(line)` from them, so any sequence a keyboard and a locale can produce arrives
  there. Only the window's text field is UTF-8 by construction.
- **CORE §8's ritual list** named neither the `pkgrel` bump nor the `changelog.Debian` stanza,
  though P18's own pin made the stanza a *build* prerequisite.

## The decisions, as ruled

| | Question | Ruling |
| --- | --- | --- |

| D2 | The two P18 nominations | **Both in scope — the round P18 planned** |
| D3 | The tag for the corrected build | **`v1.2.0-3`**, and `v1.2.0-2` demoted to pre-release |
| D4 | The header cosmetics, in the maker's own new work | **Keep the dot and the blank line; restore the badge** |
| D5 | A round named in five places with no document | **Write it, and a §7 road row** |

**D3 is the one worth reading twice.** The first instinct was to delete `v1.2.0-2` and re-cut the
same name from a corrected tree. The ruling instead leaves it published and demotes it, which
keeps two things true at once: nobody who already fetched `v1.2.0-2` ends up holding different
bytes under a name they trust, and nobody arriving at the project is offered the rotten one as
Latest. It is the same instinct §7 records about `v0.1` — that a tag is a claim about what
happened, and repairing the past by rewriting it is not a repair.

**D4 keeps a distinction the round needs to make about itself.** Two of the three things flagged
in the maker's header were visible defects on the rendered page; the third was a taste call about
his own work, made by an audit that was not asked for taste. Reverting it is the difference
between reading a page and editing it.

## What gets pinned

| Claim | Pinned to | Fails when |
| --- | --- | --- |
| The libraries opened by hand | CORE §2's row ⇄ the `.deb`'s `Depends` | either list gains or loses one alone |
| The Settings panel's groups | `settings.rs`'s own `theme::section` calls ⇄ CORE §4 | the panel or the document moves without the other |
| A password that is not text | `ArchiveError::PasswordNotUtf8` | the arm goes back to meaning *no password* |

**Each was seen failing before it was trusted**, which is P17's rule and P18's:

- `core_and_the_deb_name_the_same_dlopened_libraries` — with `libwayland-egl1` pulled back out of
  `Depends` it fails saying *"CORE §2 names `libwayland-egl` among the libraries the program opens
  by hand, and the .deb's Depends declares no package beginning with it"*, which is the shipped
  defect reproduced exactly.
- `the_settings_panel_has_the_groups_core_says_it_has` — against the old two-group CORE wording it
  fails naming `Extract`, the group the document dropped.
- `a_password_that_is_not_text_is_refused_as_itself_and_not_as_a_wrong_password` — with the arm
  restored to `Password::empty()` it fails printing `Password([])`, the empty password itself.

**What the first cannot prove, said rather than left looking covered:** if the program gains a
`dlopen` that *no* document mentions, both lists agree and both are wrong. Only the running
program can show that. It is recorded as the limit rather than gated weakly, because a gate that
cannot fail is worse than a note saying there is none.

## The work

1. **CORE §2's row, `make-deb.sh`'s `Depends`, README §3.C** — all four libraries, and the row
   now says why they are easy to miss. The `PKGBUILD` is untouched: it was right.
2. **CORE §4's popup 5, README §4, `settings.rs`'s citation** — three groups, named, with the
   **Clear list** button stated because it is the only destructive control in the panel. The
   citation points at §4's popup 5 rather than a subsection that does not exist.
3. **README §2** — `git`, and a note that the list is the one `PKGBUILD` declares.
4. **`inspector.rs`** — one `Ratio` field, in the arm that already knows the packed size. The
   `None` arm is untouched: a 7z member sharing a compression block has no packed size of its
   own, and a ratio computed from a number never reported would be an invention.
5. **`cli.rs`'s help and README's code block** — `--long`'s `path` column named in both. The
   README quotes the help, so the two move together or not at all.
6. **`sevenz.rs` and `arch.rs`** — `password_of` returns `Result`, `ArchiveError` gains
   `PasswordNotUtf8`, and its sentence says the password was never tried. Three call sites carry
   it the way each can: `list_all` and `read_member` by `?`, `Writer::create` through its `String`
   error, and `solid_info` by `ok()?` — that one reports detail or nothing and has no way to carry
   a reason, which is written down rather than left looking like an oversight.
7. **README's header** — the dangling separator and the blank line of trailing spaces. Per D4 the
   Debian badge's `%20` label is restored, and the Display Server badge's raw spaces were never
   touched: they render identically, camo encoding them and serving the same image.

## Deviations

1. **The round's first commit swept in four changes its message did not name.** `git add
   CORE.md README.md …` was run when both files already held every edit of the round, so the
   library commit carried the Settings, `git`, `--long` and cosmetic changes as well, and the
   commits after it had little left. **This is P17's Deviation 5 exactly**, in its subtler form:
   the paths were explicit, but a file held more than one logical change and staging the file
   took all of it. Caught before anything was pushed. The fix was to reset to the base commit,
   reconstruct each intermediate file state from the base by replaying the edits in order, assert
   the reconstruction reproduced the finished files byte-for-byte, and recommit — after which
   every commit touches only the files its message names and every README change is a single
   region. **The rule needs restating with the sharper edge: stage the paths a commit's message
   names, and if a file holds two changes, the file is not the unit.**
2. **Two flagged items were withdrawn before they reached the maker, by checking them.** The size
   badges were suspected of a unit error — `9.81` and `6.91` are MiB where the previous `7.2` was
   decimal MB — and GitHub's own release page prints exactly those two figures for those assets,
   so they were read off the page and match it. The Display Server badge's raw spaces were
   suspected of not rendering; camo encodes them and serves an SVG identical in byte count to the
   `%20` form. **Both would have been findings if the report had trusted the reading**, which is
   the round's own rule applied to the round.
3. **The tagline change is recorded as an observation and not a defect.** The front page and the
   repo description both now lead with *"The Most Verbose Archive Manager"*, while `CORE.md` §1,
   `about.rs`, the `.deb`'s `Description:` and four test doc comments still lead with *"the
   metadata is the main event"*. CORE wins by rule, so nothing is false; the shop window and the
   governing document simply open with different sentences now, and which is wanted is the
   maker's to say. Nothing in this round changed either.
4. **`P2.md`'s "CORE §4.5" citation is left standing.** `settings.rs` copied it and is corrected;
   `P2.md` is not, because a P-document records what its round believed and is annotated, never
   rewritten. The section numbering it names was real when it was written.
5. **The `.deb`'s dependency gap is fixed in the tree and was shipped.** `v1.2.0-2` is published
   with a package that under-declares. D3 rules how that is handled — demotion rather than
   deletion — but the artefact on that page stays wrong for as long as it stays up, and saying so
   is the honest half of choosing not to delete it.

## The ritual

CORE §8, with the two steps this round added to it.

1. **`Cargo.toml` stays `1.2.0` and `pkgrel` becomes `3`**, so `release.yml`'s derivation accepts
   only `v1.2.0-3`. Checked by running that derivation against the tree, not by reading it.
2. `changelog.Debian` gains a stanza whose first line is exactly
   `indium (1.2.0-3) unstable; urgency=medium`, and **`RELEASE_DATE` moves to that stanza's date
   in the same commit** — P18's pin fails the build otherwise.
3. `README.md`: the three install filenames moved to `1.2.0-3`, the badges re-measured off the
   artefacts this tag publishes, and the screenshots retaken.
4. Commits in the house voice, from **sudo-megas**, no AI attribution anywhere.
5. Push. `ci.yml` green. Then `gh workflow run release` — the dispatch before the tag, because
   packaging is never proven on this machine.
6. Dispatch green → **verify the rehearsal `.deb` actually declares `libwayland-egl1`**, which is
   the one thing this round exists to ship → tag `v1.2.0-3` → tag run green → download its three
   artefacts → `gh release create v1.2.0-3`.
7. **`v1.2.0-2` marked pre-release**, per D3, so it stays readable and stops being offered.

**Steps 5 to 7 wait for the maker's signal.** Local verification is done; push, tag, release and
the demotion are his, as is every box above that needs a person at a running program.

- **No yazi plugin.** V1.3 was raised and set aside by the maker for this session; §7's condition
  on it — that the Inspector's verbosity genuinely beat a plain listing — has still not been
  judged, and §7 also says the plugin is versioned separately and can take no INDIUM tag. That
  tension is worth settling before the work starts, not during it.
- **No new dependency**, and no new parser that is not hand-rolled.
- **`sidebar.rs`'s dead `"soon"` branch stays**, its comment corrected in place by P18. Deleting
  a branch is a code change, and this round already touched behaviour twice.
- **The tagline is not restored, and CORE §1 is not rewritten to match it.** Deviation 3 records
  the divergence; deciding it is not an audit's job.
