# P1 — Open, list, inspect, extract

*Implements CORE.md §1–§6 for the read path. When this file and CORE.md disagree, CORE.md wins.*

**Goal in one sentence:** launch INDIUM, open any supported archive, see more about its
contents than any other tool on Linux shows, and extract what you select — tagged `v0.1`.

**Not in P1** (so nobody "helpfully" adds them): creation, staging/Apply, encryption,
encrypted-read prompts, Preview tab, clipboard copy-out, Open With, Recent files,
Bookmarks, Settings, packaging. They have their own P-documents.

## 2. `arch` — the libarchive FFI

Link the system library: `build.rs` with
`println!("cargo:rustc-link-lib=dylib=archive");`. No `-sys` crate, no bindgen — a
hand-declared `extern "C"` block of exactly what INDIUM uses:

`archive_read_new`, `archive_read_support_filter_all`,
`archive_read_support_format_all`, `archive_read_open_filename`,
`archive_read_next_header`, `archive_read_data_block`, `archive_read_data_skip`,
`archive_read_extract`, `archive_read_close`, `archive_read_free`,
`archive_format`, `archive_format_name`, `archive_error_string`,
and the entry getters: `archive_entry_pathname`, `archive_entry_size`,
`archive_entry_mtime` / `atime` / `ctime` / `birthtime` (with their `_is_set` checks),
`archive_entry_uid` / `gid` / `uname` / `gname`, `archive_entry_mode`,
`archive_entry_filetype`, `archive_entry_symlink`, `archive_entry_hardlink`,
`archive_entry_is_encrypted`.

Over that, a safe wrapper in the same module:

- `ArchiveReader::open(path)` → errors become `String`s from `archive_error_string`.
- **The RAR gate (CORE §5):** after the first successful `next_header`, check
  `archive_format` — if the format name contains `RAR`, close and return the exact
  sentence *"RAR is not supported."* This is the only format INDIUM refuses.
- `list()` runs on the worker thread and sends `Entry` structs over an
  `std::sync::mpsc` channel as headers stream in — the table fills while a huge
  archive is still being read.
- `extract(entries, dest)` re-opens the archive and extracts matching paths with flags
  `ARCHIVE_EXTRACT_TIME | PERM | ARCHIVE_EXTRACT_SECURE_SYMLINKS |
  ARCHIVE_EXTRACT_SECURE_NODOTDOT`, chdir-free (prefix `dest` onto the entry pathname
  via `archive_entry_set_pathname`). The secure flags are not optional — they are what
  stops a hostile archive writing outside `dest`.
- Progress: entries done / entries total over the channel; a shared `AtomicBool`
  cancels between entries.

Two things libarchive will not give you, so the wrapper is honest about them: there is
no stored-CRC getter — `crc32(path)` streams the entry through a hand-written
256-entry table implementation, on request only, and the UI labels the value
*computed*; and 7z solid-block detail is out of reach until `sevenz-rust2` lands in P4.

`Entry` carries: path, is_dir, size, packed size where the format reports it, method
name, the four timestamps as `Option`, uid/gid + names, mode, symlink/hardlink target,
encrypted flag.

## 3. The window skeleton

`model` holds `AppState`: current archive (or none), entries, selection set, current
directory within the archive, worker handle, progress.

Zones per CORE §4, built in this order so each is testable as it lands:

1. **Frame + status bar.** Reactive repaint from the start:
   repaint only on input and on worker messages (`ctx.request_repaint()` from the
   channel side). An idle INDIUM must sit at zero GPU.
2. **Sidebar.** Wordmark, *Recent files* `1`, *Bookmarks* `2`, *Archive* `3`, *New*
   `N`, *Settings* `,`, *About* `A`. In P1 only *Archive* and *About* are live; the
   rest render muted with a small `P2` tag — present, honest, inert. About follows
   CORE §4.6: selectable addresses, nothing clickable.
3. **Entry table.** `egui_extras::TableBuilder`, virtualized rows, columns Name /
   Size / Packed / Method, breadcrumb above. `Enter` descends, `Backspace` ascends —
   directory structure is derived from entry paths, not trusted from the archive.
4. **Inspector, Details tab only.** Every `Entry` field, mono type, in the CORE order:
   sizes, ratio bar, method, CRC (with its *compute* action), timestamps, owner,
   mode as `-rw-r--r-- 644`, link target, encryption state. Multi-select: count,
   total real, total packed, ratio. No selection: the archive card — format name,
   entry count, totals, path. The Preview tab renders as a disabled stub.
5. **Extract popover** on `E`: *Extract here*, *Extract to `<archivename>/`*, path
   field with tab completion against the filesystem. Bookmarks row stubbed for P2.
   Extraction runs on the worker; progress and a working cancel in the status bar.
6. **Theme.** `theme` module with the CORE §6 values as constants; Ubuntu Sans and
   Ubuntu Mono into `assets/fonts/` with `LICENSES/UFL-1.0.txt`, embedded via
   `include_bytes!` + `FontDefinitions`; then delete `default_fonts` from
   `Cargo.toml`. Orange only on selection and progress — nothing else is orange yet,
   because nothing else stages or applies yet.

Opening: `indium <path>` via `std::env::args`, plus dropped files
(`raw_input.dropped_files`), plus `Ctrl+O` path field. Keyboard per CORE §4's table,
minus the keys whose features aren't in P1.

## 4. Fixtures and tests

`tests/fixtures/` gets small committed archives, with a `fixtures/README.md` recording
the exact commands that made them (all via `bsdtar`/`python3` on the build machine —
INDIUM itself never shells out, its test *fixtures* may be born however convenient):

- `basic.zip`, `basic.tar.gz`, `basic.tar.zst`, `basic.7z` — same three files + one
  subdirectory each, known sizes.
- `meta.tar` — entries with a symlink, a hardlink, explicit uid/gid, and old mtimes.
- `evil.zip` — one entry named `../escape.txt` (made with a two-line Python
  `zipfile` script, recorded in the README).
- `secret.zip` — one AES-encrypted entry (its *listing* must work in P1; reading its
  data is P2's password prompt).

`cargo test` covers, at minimum: each `basic.*` opens and lists the expected entry
count and sizes; `meta.tar` round-trips symlink target, uid/gid, and mtime into
`Entry`; extraction of `basic.zip` to a tempdir reproduces byte-identical files;
`evil.zip` extraction **fails** and `escape.txt` does not exist outside the tempdir;
`crc32` of a fixture file matches a precomputed constant; a `.rar` header (tiny
hand-written magic-bytes fixture) is refused with the exact sentence.

Manual checklist before release — run each, tick each:

- [ ] `indium basic.7z` opens to a filled table in under a blink
- [ ] a directory descends on `Enter` and returns on `Backspace`
- [ ] Inspector updates on arrow-key movement without lag
- [ ] multi-select shows aggregates
- [ ] `E` → Extract here produces the files beside the archive
- [ ] Extract to path with tab completion works to a deep directory
- [ ] cancel during extraction of a large archive actually stops it
- [ ] idle window sits at 0% GPU (`nvtop`/`btop`)
- [ ] `./build/check-deps.sh` passes

`build/check-deps.sh`:

```sh
#!/bin/sh
set -e
out=$(ldd target/release/indium)
echo "$out"
for bad in gtk Qt KF6 X11 portal; do
  echo "$out" | grep -i "$bad" && { echo "FAIL: $bad linked"; exit 1; }
done
echo "OK: toolkit-free"
```

## Deviations

*(recorded during implementation; empty is a valid state)*

1. **egui/eframe pinned at 0.36.1, not 0.29.** §1 permits this outright — "Pin whatever
   current versions resolve at implementation time; the feature flags are the contract,
   not the numbers." Worth knowing that the API moved a long way: `eframe::App` now
   requires `fn ui(&mut self, ui: &mut Ui, …)` rather than `update(&mut self, ctx, …)`,
   and `SidePanel`/`TopBottomPanel` are gone, replaced by one `egui::Panel` with
   `left/right/top/bottom` constructors that are shown *into a `Ui`*. The feature list
   is exactly `glow`, `wayland` as CORE §2 requires; `default_fonts` was scaffolding and
   is gone as step 6 orders.

2. **The RAR gate as §2 words it never fires.** §2 says "after the first successful
   `next_header`, check `archive_format`". On a RAR, libarchive returns `ARCHIVE_EOF` —
   never `ARCHIVE_OK` — and `archive_format` is `0` until after that call, so there is no
   successful header to hang the check on and the archive would simply look empty.
   Implemented instead as two checks with the same observable behaviour: the RAR
   signature is read from the file's first bytes *before* libarchive is involved
   (deterministic, and it still produces the exact sentence on a libarchive built
   without RAR support at all), and the format is checked after the first
   `next_header` **regardless of return code**. The sentence CORE §5 fixes is
   unchanged.

3. **The secure flags are not sufficient on their own, and §2 says they are.** §2 states
   the flags "are what stops a hostile archive writing outside `dest`". With extraction
   done chdir-free — prefixing an absolute `dest` onto the stored name, exactly as §2
   prescribes — libarchive does *not* refuse a `..` component, and `evil.zip` extracted
   successfully. Caught by `a_traversal_entry_is_refused_and_writes_nothing`. INDIUM now
   judges the stored path itself (`arch::path_escapes`): any absolute path or `..`
   component is refused before extraction begins, and re-checked inside the extraction
   loop because the archive is read twice. The secure flags remain set as a second line.

4. **Per-entry packed size and method are not available.** libarchive exposes no
   per-entry compressed-size getter, so `Entry::packed` is always `None` and the Packed
   column reads "—" with a note. Method comes from the archive-level filter name
   (gzip/xz/zstd/…), or from the zip format-name parenthetical, which libarchive updates
   per entry. 7z per-entry detail waits for `sevenz-rust2` in P4, as CORE §4 already
   says. This matches CORE's existing honesty note about the stored CRC.

5. **Glyphs.** Removing `default_fonts` leaves no fallback face, and the embedded Ubuntu
   files carry none of `▸ ✕ ☆ 🔒 →` (verified against their `cmap` tables). Directories
   are marked with a trailing `/`, remove buttons use `×` (U+00D7), the bookmark pin is
   `+`, an encrypted entry is tagged `enc`, and arrows are `->`. Em dash and middle dot
   are present in both faces and are used as written.

6. **The mono face is Ubuntu Sans Mono, not Ubuntu Mono.** CORE §2 and §6 name "Ubuntu
   Sans" and "Ubuntu Mono". The `Ubuntu-Sans-fonts` repository ships no mono face, and
   the classic "Ubuntu Mono" belongs to the 2011 family whose proportional face is named
   plainly "Ubuntu" — so the two names in CORE do not come from one family. Shipped as
   the matched modern pair, both verified Ubuntu Font Licence 1.0. **This is a CORE
   question and no CORE edit was made**, because none was ordered — it is the maker's
   call.

7. **`TempDir` is hand-written in the tests** rather than pulling `tempfile` as a
   dev-dependency. CORE §2's rule is applied to test dependencies too: "makes a
   directory in /tmp" does not fill in a sentence worth a crate.
