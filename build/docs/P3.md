# P3 — Out into the system

*Implements CORE.md §3–§4 `platform` and §8 registration. When this file and CORE.md
disagree, CORE.md wins.*

**Goal in one sentence:** files leave INDIUM the two ways files leave anything — pasted
into any file manager, or opened in the right application — and the desktop learns that
archives belong to INDIUM — tagged `v0.3`.

**Not in P3:** staging, Apply, creation, 7z writing (P4); Preview (P5); packaging and
system-wide install (P6). Registration here is for the dev machine, user-scope.

## 1. `platform::scratch` — where copies live

Both features below hand real files to the outside world, so both need a scratch area
with rules:

- Root: `$XDG_RUNTIME_DIR/indium/`. That directory is tmpfs — **RAM** — so there is a
  guard: sum the uncompressed sizes of the selection first, and above **1 GiB** route to
  `$XDG_CACHE_HOME/indium/scratch/` on disk instead, with a one-line status notice.
  Constant in P3, not a setting.
- `$XDG_RUNTIME_DIR` can be legitimately unset — CORE §9 permits running as root, and
  root often has none. Same cache fallback, silently.
- Layout: one subdirectory per operation, `co-<n>` for copy-out, `ow-<n>` for Open With.
  Starting a new operation of a kind removes the previous directory of that kind; a drop
  guard removes everything of ours on clean exit; the runtime dir's logout wipe is the
  backstop for unclean ones. Stale `scratch/` cache entries are swept at launch.
- Extraction into scratch is P1's extractor, secure flags and all, relative paths
  preserved.

## 2. `Ctrl+C` — copy-out

The mechanism that replaced drag-out (CORE §9), and it must feel better than drag, not
apologetic about it.

Flow: selection → extract to a fresh `co-<n>` scratch dir → build `file://` URIs →
offer on the Wayland clipboard → status line *"3 files ready to paste"*. Paste in any
file manager completes it; it also works from a filtered selection, and an encrypted
selection rides P2's password flow first.

**URI building is hand-written and unit-tested** (CORE §2: no crate for twenty lines):
percent-encode every byte outside RFC 3986 unreserved (`A–Z a–z 0–9 - . _ ~`), keeping
`/` as the separator; space is `%20`, never `+`; paths are absolute; lines end `\r\n`
per the spec.

**The offer** uses `wl_clipboard_rs` copy with *two* MIME sources: `text/uri-list` and
`text/plain;charset=utf-8` (plain newline-separated paths, so a paste into a terminal
does something sensible too). Known and deliberate for now: Nautilus's paste-as-copy
wants a third type, `x-special/gnome-copied-files` (`copy\n` + the URIs) — add it in
this milestone **only if** the manual test against a GNOME file manager fails without
it, and record the addition in Deviations either way.

Honest behavior to state in the release notes: the offer lives as long as INDIUM does.
Close INDIUM before pasting and the clipboard is empty — that is Wayland, and a
clipboard manager is the user's own business, not a dependency INDIUM grows.

## 3. `platform::apps` + Open With

`Enter` (or double-click) on a file entry: extract that one file to an `ow-<n>` scratch
dir — password flow applies if needed — then the picker popup (CORE §4.4).

**Scanning**: `.desktop` files from `$XDG_DATA_HOME/applications` and every
`$XDG_DATA_DIRS/applications` (defaults `~/.local/share`, then
`/usr/local/share:/usr/share`), first-found-wins by desktop-file ID. Parsed fields:
`Name`, `Exec`, `MimeType`, `NoDisplay`, `Hidden`, `TryExec`, `Terminal`. `NoDisplay`
and `Hidden` are honoured; a `TryExec` that is not on `$PATH` disqualifies;
`Terminal=true` entries are listed but launch via nothing special — they get the same
spawn, which on a compositor without a terminal wrapper may do nothing, and that is the
entry's problem, not INDIUM's. Icons are deliberately not rendered in v1: icon-theme
resolution is a subsystem, the list is text, and the one-sentence rule of CORE §2
applies to features too.

**MIME of the inner file**: a built-in extension→type table of about forty common
types, `application/octet-stream` as the honest fallback. Parsing the shared-mime-info
database is a later temptation, recorded here as deliberately skipped.

**Ranking**: the `~/.config/mimeapps.list` `[Default Applications]` entry for the type,
tagged *default*, first; then exact `MimeType` matches; a *Show all applications*
toggle reveals the rest. Filter-as-you-type, as everywhere.

**Launching**: expand the Exec field per the Desktop Entry spec — `%f`/`%F` become the
scratch path, `%u`/`%U` its `file://` URI, `%i`/`%c`/`%k` are stripped — with a
tokenizer that honours the spec's quoting and escaping (~40 lines, unit-tested against
nasty real-world Exec lines). Spawn detached in its own process group
(`CommandExt::process_group(0)`): closing INDIUM must never take the viewer down
with it.

One permanent line in the popup footer, always visible, so it never becomes a bug
report: *"Opens a copy — changes won't return to the archive."*

## 4. Registration — becoming the default

`assets/org.indium.desktop`, exactly CORE §8: `Exec=indium %f`, `Terminal=false`,
`Categories=Utility;Archiving;`, `Icon=indium`, and the full MIME list with
`application/vnd.rar` deliberately absent.

`build/install-desktop.sh` (dev machine, user scope — packages redo this system-wide in
P6):

```sh
#!/bin/sh
set -e
install -Dm644 assets/org.indium.desktop \
  "$HOME/.local/share/applications/org.indium.desktop"
for png in assets/icon/*.png; do
  [ -e "$png" ] || continue
  size=$(basename "$png" .png)
  install -Dm644 "$png" \
    "$HOME/.local/share/icons/hicolor/${size}x${size}/apps/indium.png"
done
command -v update-desktop-database >/dev/null &&
  update-desktop-database "$HOME/.local/share/applications" || true
if [ "$1" = "--set-default" ]; then
  xdg-mime default org.indium.desktop \
    application/zip application/x-7z-compressed application/x-tar \
    application/gzip application/x-xz application/zstd application/x-bzip2 \
    application/x-lzip application/x-cpio application/x-iso9660-image \
    application/x-compressed-tar application/x-xz-compressed-tar \
    application/x-zstd-compressed-tar application/x-bzip2-compressed-tar
fi
```

The icon loop tolerates an empty `assets/icon/` — the maker supplies the PNGs on his own
schedule, and their absence must not block `v0.3`. Without `--set-default` the script
installs and touches nothing about the user's choices; with it, INDIUM takes the
formats. Both modes are the user's call, run by hand.

Multiple windows on one archive are permitted and safe today — everything is read-only
until P4. **Forward-pointer for the P4 document:** Apply takes an advisory lock on the
archive path so two windows cannot rebuild the same file; that requirement lives here
until P4.md exists to own it.

## Deviations

*(recorded during implementation; empty is a valid state)*

1. **`x-special/gnome-copied-files` was NOT added, and the GNOME test was not run.**
   §2 requires this recorded "either way". The machine runs a Plasma session with no
   GNOME file manager installed, so the condition §2 attaches the third MIME type to —
   "only if the manual test against a GNOME file manager fails without it" — could not
   be evaluated. Two types are offered, `text/uri-list` and `text/plain;charset=utf-8`,
   and both were verified live: `offer_reaches_the_wayland_clipboard` (an `#[ignore]`d
   test, run deliberately) drives a real `wl-paste` and asserts the URIs come back
   correctly encoded, space and UTF-8 included. If a paste-as-copy into Nautilus turns
   out to need the third type, that is a one-line addition here.

2. **The Exec tokenizer needs two passes, and a single pass is silently wrong.** §3 asks
   for "a tokenizer that honours the spec's quoting and escaping (~40 lines,
   unit-tested against nasty real-world Exec lines)". The first implementation did one
   pass and produced **two** backslashes where a wine entry's `\\\\` means **one** —
   caught by the committed `quoting.desktop` fixture. The spec is explicit that the
   general string-value escape rule "is applied before the quoting rule", so
   `unescape_value` now runs first and the quoting pass second. Inside double quotes
   only `"`, `` ` ``, `$` and `\` are escapable; any other backslash stays literal, as
   in a shell. The expected argv was cross-checked against GLib's own
   `g_shell_parse_argv`.

3. **Partial quoting follows the shell reading.** `WINEPREFIX="/home/megas/.wine"` opens
   a quote mid-argument. The spec only says arguments may be quoted *in whole* and does
   not define this case; every real implementation (GLib, wine) reads it shell-style and
   drops the quotes, so INDIUM does too, yielding `WINEPREFIX=/home/megas/.wine`.

4. **A missing `Exec` binary does not disqualify an entry — only `TryExec` does**, which
   is exactly what §3 specifies. Worth writing down because GLib's own loader *also*
   drops entries whose `Exec` program is not on `$PATH`, so INDIUM will list a few
   entries a GTK picker hides. The fixtures were built so each keep/skip outcome is
   attributable to one field, and they would not mask a change of mind here.

5. **`Enter` on a file now opens the picker.** In P1 `Enter` only descended into
   directories and did nothing on a file. That is what §3 asks for, but it is a change
   to a key already in CORE §4's table, so it is noted rather than assumed.

6. **The P4 forward-pointer has nowhere to go yet.** P3's "done when" requires the
   advisory-lock requirement to be "carried into `P4.md` when it is written". `P4.md`
   does not exist — P3 itself says it is written once `v0.3` is tagged — so the
   requirement stays here, unmoved: **Apply must take an advisory lock on the archive
   path so two windows cannot rebuild the same file.** It must be transcribed into
   `P4.md` at the moment that document is created.

7. **Four manual checklist items still need a human at the machine**, and were not
   ticked: pasting into a GUI file manager; a copy-out above 1 GiB (the fixture is
   explicitly not committed); launching a viewer and then closing INDIUM to prove the
   viewer survives; and `install-desktop.sh --set-default` followed by `xdg-open`,
   which changes the user's real MIME associations and is not something to do to
   someone's session unasked. Everything automatable was automated — the URI encoding,
   the Exec tokenizer, `.desktop` parsing and ranking against committed fixtures, MIME
   resolution, and scratch routing are all covered by tests, and the clipboard offer was
   verified against a live compositor.
