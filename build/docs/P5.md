# P5 — See it, and be seen

*Implements CORE.md §4's Preview tab, §6's palette, and §7's icon integration. When this
file and CORE.md disagree, CORE.md wins.*

**Goal in one sentence:** the Inspector shows what a file *is* and not merely what an
archive says about it, the window is legible and carries the maker's mark, and everything
P4 delivered into the library finally reaches the program — tagged `v0.5`.

**Not in P5:** hex view (V1.1); packaging, `.pkg.tar.zst`, `.deb`, the README and
hardening (P6). Registration here is still the dev machine, user scope.

## 1. What P4 left open

P4 is tagged and its Deviations are honest about what it deviated from. They are silent
about two things it simply did not do, and P5 opens by closing them, because a document
that describes behaviour the code does not have is the one failure this project treats as
unforgivable.

**The streaming list did not route 7z.** `arch::list_all` did — the path the tests use.
The window runs `arch::list`, which opened a libarchive reader directly and never asked.
So everything P4 delivered reached the test suite and none of it reached a user: a 7z
showed no packed sizes, the Method column said `7z` rather than the coder its block
actually uses, and an encrypted-header archive could not be opened at all. The regression
test for this asserts the **method**, not the packed size — `basic.7z` is solid, so packed
is `None` under either routing and an assertion on it would pass while the bug was still
there.

**The solid-block detail was never shown.** CORE §4 promised it in P4, `sevenz::solid_info`
was written and tested, and its only caller in the whole repository was a test.
`ArchiveInfo` gains `solid` and `blocks`, `None` for every format but 7z, and the archive
card gains two rows.

**And the data fallback P4 §4 described was never built.** Its own words: *"Data —
extraction, CRC32, passphrase checks — goes to libarchive first, and to `sevenz` only
where libarchive refuses."* No such fallback existed. It was latent only because the
window could not open an encrypted-header archive at all — and making it listable is
exactly what would have turned that into a hole, with an archive that lists and then
refuses every read. Two things had to be right:

- **The refusal does not come from `Reader::open`,** which succeeds. Opening the file is
  fine; it is the first *header* libarchive cannot decrypt. So the fallback keys on the
  error the read actually produces, not on the open failing.
- **Extract's pre-flight verified the password through libarchive,** which fails on such
  an archive for a reason that has nothing to do with the password. The listing already
  succeeded, and an encrypted-header archive cannot be parsed at all without the right
  password — so reaching that line *is* the verification.

`on_list_failure` also had to learn two new errors. libarchive reports `EncryptedHeaders`;
the 7z reader, which can open such an archive once it has the password, reports
`NeedPassword` or `WrongPassword`. Without that the routing would have failed to a status
line with no prompt behind it, while a library-level test supplying the password passed.

## 2. The Preview tab

CORE §4: *"Preview renders text and images (hex arrives at V1.1)."*

**Getting the bytes.** There was no way to read an entry into memory: `crc32_of` consumed
them as it went and `extract` only ever wrote to disk. `arch::head_of` is shaped like
`crc32_of` and built on P4's `EntryData`, so `archive_read_data`'s short-read and
sparse-hole behaviour is shared with the rebuild path rather than derived a second time,
and it takes the same libarchive-first routing as everything else.

**The cap is not a nicety.** An archive is untrusted input and a member may be gigabytes;
a preview that read all of one would be a way to make the window disappear. Eight
megabytes, and the read takes one byte past it so *"there is more"* is known without a
second pass.

That flag is a **gate**, not a footnote. A head is enough to *sniff* an image and never
enough to *decode* one — a truncated PNG handed to a loader produces a confusing error
where an honest sentence belongs. So an entry over the cap is sniffed, named, and refused
a decode.

**What a file is, judged from its bytes.**

- **An image is recognised by its magic and never its extension.** A PNG named `notes.txt`
  is a PNG. Reporting what is actually there rather than what a name claims is the same
  principle that makes the Inspector worth having at all.
- **Text means no NUL byte and valid UTF-8** — checked, not assumed. Lossily decoding
  arbitrary bytes into replacement characters would be inventing content, which is the one
  thing this program does not do.
- **Neither gets a sentence.** CORE §4 reserves hex for V1.1, so a half-built hex view
  would be worse than saying plainly that there is nothing truthful to show.

**Only the archive read needs a worker.** `egui_extras` decodes on its own background
thread and repaints itself; the thread here exists because `arch::Reader` is not `Send`, so
only the path and the passphrase cross the boundary and the worker opens its own reader.
An encrypted entry rides P2's park-and-resume path exactly as a checksum does.

**Every previewed image is forgotten** from egui's texture cache when the selection moves.
Without that, browsing a few hundred photographs would keep all of them for the life of
the process.

**Formats:** PNG, JPEG, GIF and BMP, every one a pure-Rust decoder, verified against the
dependency tree rather than assumed. TIFF is deliberately absent — its C-freedom rests on
an upstream crate's default continuing to exclude an optional `zstd` feature, which is
someone else's decision to change. WebP is absent as one more decoder for a format common
on the web and rare inside an archive.

## 3. The look-and-feel pass

`theme.rs` carried colours and fonts and **never once touched `Style::spacing` or
`text_styles`**, so egui's defaults quietly owned the two most prominent sizes in the
program — 13.0 for every unstyled label and button, 18.0 for every popup title — neither
of which appeared anywhere in the source. Writing them down was most of the fix.

**Aubergine stops being a text colour.** At `#772953` on the panel it measured **1.74:1**,
below the point at which type is legible at all, and it was applied at 10px bold to every
section heading in the Inspector — the pane CORE §1 calls the main event. §6 assigns
Aubergine no text role; it lists only the three Text tiers. It was always a category
error, and it keeps every *fill* use it has. The `.to_opaque()` beside it was a no-op at
all six sites.

**Buttons, text fields and the checkbox were invisible.** `widgets.inactive`'s fills were
`PANEL` and popups are `PANEL`, so a button was a bare label in a box at 1.08:1 with a
hairline at 1.25:1, and an unfocused text field had no boundary whatsoever. P4 diagnosed
exactly this on the slider and patched it inside one popup; the cause was always in
`theme.rs`, so the local patch is deleted and the fix is where it belongs.

**`widgets.active.bg_stroke` was orange,** which put CORE §6's accent around every pressed
widget — Cancel, Discard, Clear list, the checkbox. Orange as a generic press affordance is
decoration, which the comment on the constant forbids in its own words.

**Scrollbars were floating** with zero dormant opacity and zero allocated width: invisible
until hovered and painted *over* content rather than beside it. The Inspector had no cue
that it scrolled.

**The table's Name column** had no size and no family, so it inherited 13.0 proportional
and sat 18% larger than the three mono columns beside it, in every row of the main view.

**The palette itself** is the maker's, and recorded in §6 rather than here: `#300A24` for
the ground — his own terminal, and at hue 319° a closer relative of Canonical Aubergine
(328°) than the 288° it replaced — `#EEEEEC` for text, and `#FFD800` for the one meaning
orange was wrongly carrying.

## 4. The icon, and a window that says which archive it holds

The maker's icons live in `build/icons/` as masters, 16 through 4096. They stay there
rather than moving to `assets/`: most of the set is never installed, and `build/` is where
inputs to the build belong. `assets/icon/`, created empty by P3 and read by nothing, is
removed.

`install-desktop.sh` gains **`gtk-update-icon-cache`**. It ran `update-desktop-database`
and nothing else, which rebuilds MIME associations and does nothing whatever for icons —
and where an `icon-theme.cache` already exists, which it usually does, GTK trusts the cache
and never sees a newly installed `indium.png`.

**The title names the archive.** CORE §1 has one archive per window and no tabs, so the
intended workflow is several windows — every one of which was labelled `INDIUM`, identical
in the compositor, the switcher and the taskbar, with no way to tell them apart short of
focusing each in turn. The information was already sitting on `archive_path`.

The window icon is set from the 256 master. On Wayland the app id is what actually
resolves an icon; this is the belt to that brace.

## 5. Fixtures and tests

No new fixtures. Everything P5 needs is already committed, and the two that carry the most
weight are `basic.7z` — solid, one block, three files — and `secret-headers.7z`, whose one
member owns its block and whose payload the fixtures README records.

`cargo test` additions, at minimum:

- the streaming list names the coder a 7z actually uses — the regression test for §1, and
  it asserts the **method**, since packed is `None` under either routing on a solid archive
- a solid archive reports itself solid through the streaming list, and a zip reports
  nothing rather than inventing a block structure
- an encrypted-header 7z opens through the streaming list, refuses without the password,
  and reports its packed size as `Some(48)` with it
- an encrypted-header 7z entry can be read, and extracted, after the prompt — §1's fallback
- an image is recognised by its bytes and not its extension
- a file with a NUL byte is not offered as text
- non-UTF-8 bytes are reported rather than lossily decoded
- two bytes are not enough to call something a bitmap

Manual checklist before release:

- [x] open `basic.7z`: the Method column names the coder, and the archive card reports
      solid and its block count
- [x] open `secret-headers.7z`: the password prompt appears rather than a dead status line
- [x] Preview an image inside an archive; Preview a binary and read an honest sentence
      naming how much was read
- [x] the window title names the open archive
- [x] `./build/install-desktop.sh` installs all ten sizes and exits 0
- [ ] `--set-default`, then `xdg-open` an archive — not run; it changes the user's real
      MIME associations and is his to run
- [x] `./build/check-deps.sh` still prints `OK: toolkit-free` — with four image decoders
      linked in, this run is the one that proves none of them brought C with it

```
cargo fmt
cargo clippy -- -D warnings
cargo test
cargo build --release
./build/check-deps.sh
git add -A
git commit -m "P5: preview, the look-and-feel pass, the icon"
git push
git tag v0.5
git push origin v0.5
tar czf indium-0.5-x86_64.tar.gz -C target/release indium
```

GitHub release on `v0.5`, pre-release, tarball attached, notes in the house voice —
including the eight-megabyte preview cap and what it means for a large image, and the
sentence that INDIUM decodes four image formats and says so plainly about everything else.

## Deviations

*(recorded during implementation; empty is a valid state)*

1. **P4 Deviation 6 is wrong about `CollapsingHeader`, and P4.md is not rewritten.** It
   says `show_background(true)` is *"what gives Advanced a visible affordance"*. It is
   not: the header paints `weak_bg_fill`, which was `PANEL` on a `PANEL` popup, so the call
   changed nothing visible. The affordance was always the vector triangle egui paints
   itself. A P-document is a record of what was believed at the time, so the correction
   lives here rather than being edited into history.

2. **The data fallback (§1) is not in CORE §7's P5 line.** It is in because §1 created the
   need: making an encrypted-header archive listable without it would have shipped an
   archive that opens and then refuses every read, which is worse than not opening. Doing
   half of it would have been the failure this milestone opens by describing.

3. **`selectable_label` still paints orange** on the Inspector tabs, the New Archive preset
   chips and the Settings toggle — three meanings CORE §6 does not sanction, and in direct
   conflict with the sidebar signalling the very same "this is active" state in Aubergine.
   Two colours for one meaning, in one window. It is left alone deliberately: reconciling
   them was the larger of the two polish options and the maker chose the smaller. Recorded
   so it reads as a choice rather than an oversight.

4. **The icons live in `build/icons/`, not `assets/icon/`,** because that is where the
   maker put them and because most of the set is never installed. `assets/` holds what
   ships — the fonts are embedded from there; `build/` holds inputs. `assets/icon/` is
   removed rather than left empty.

5. **Four icon sizes are derived, not drawn.** hicolor looks in 22, 24, 48 and 96, and
   **48 is the one size freedesktop actually mandates**; none were in the supplied set.
   They are Lanczos downscales of the 512 master, with the command recorded in
   `build/icons/README.md` so it is not mistaken for design work. Replace any of them by
   hand and nothing else changes.

6. **The two largest masters are gitignored.** `indium-2048.png` and `indium-4096.png` are
   21 MB between them, are used by nothing, and would sit in history forever. Everything
   the program and the installer touch — 16 through 1024 — is committed. Two lines out of
   `.gitignore` reverses it.

7. **Every font size went up two pixels**, by the maker's eye rather than by measurement.
   The scale set earlier in this milestone was coherent and small. The four roles in
   `theme.rs` moved with the explicit call sites, so only the floor rose.

8. **`with_icon` was going to be skipped and then was not.** The plan reasoned that
   `include_bytes!` on a file that did not exist would break the build and destroy the
   tolerance P3 §4 built in. The maker supplied the icons mid-milestone, so the objection
   evaporated and the line went in.

9. **The Preview screenshots were taken by temporarily defaulting the Inspector tab**, not
   by driving the window. Simulating keystrokes raised a desktop permission dialog asking
   for standing input-device control, which is not a thing to accept on someone's behalf.
   The default was reverted before the commit and is `Details`, as CORE §4 requires.

10. **The manual `--set-default` box is unticked.** It rewrites the user's real MIME
    associations, and P3 §4 already ruled that both modes are his call, run by hand.
