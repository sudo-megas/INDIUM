# P20 — the plugin that could not live where CORE said, and the description the maker settled on

## Why this round

Two things had been waiting on a decision rather than on work, and both decisions arrived.

**CORE §7 has carried the yazi plugin as a conditional since `c5fc8c5`, 8 August**, in one
sentence holding three constraints: *"built only if the Inspector's verbosity genuinely beats a
plain listing — judged then, in `contrib/`, versioned separately."* A gate, a location, and a
versioning rule. None had been discharged. The maker was asked what the plugin was originally
*for* and the honest answer out of the record was that the motive was never written down beyond
that sentence — the condition **is** the motive in shorthand: yazi's archive preview is a plain
listing, and INDIUM knows more about an archive than a plain listing shows.

**P19 §Observations 3 left the tagline split open and said whose it was:** the front page and the
GitHub description had come to lead with *"The Most Verbose Archive Manager for Linux on
Wayland"*, while `about.rs`, the `.deb`'s `Description:` and `CORE.md` §1 still led with *"the
metadata is the main event"*. That round recorded it as an observation, not a defect, and closed
with *"which is wanted is the maker's to say. Nothing in this round changed either."* He said.

## The gate, measured rather than asserted

A gate that cannot return "no" is not a gate, so both halves are written down.

| | yazi 26.5.6's built-in | `indium list --long` |
| --- | --- | --- |
| Shows | name, human size, icon, tree depth | mode, octal mode, size, **packed**, **method**, **encryption**, timestamp, path, **totals** |
| Needs | an external `7zz` or `7z` | nothing but `indium` |
| On this machine | **nothing at all** — no 7-zip installed | works |

Four fields against eight, and a second argument CORE could not have anticipated when it wrote the
condition: **yazi's previewer shells out to 7-Zip, which is precisely what §9 forbids INDIUM from
ever doing.** So the plugin works where the built-in cannot, including on the machine it was
written on, where hovering any archive printed *"Failed to start either `7zz` or `7z`. Do you have
7-zip installed?"*

The comparison was read off a real screen. yazi is a full-screen program and this session had no
controlling terminal, so it was driven inside a pty and its output rendered through a terminal
emulator — every claim in this document about what a pane shows was **seen**, not reasoned about.

## Where it lives, and why `contrib/` was never possible

`ya pkg` — the tool every yazi plugin is installed with, including the three already on this
machine — clones a repository's **default branch** and expects the plugin at the repository
**root**, and its `rev` takes a commit hash rather than a branch or a tag. Three consequences,
none of them a preference:

- a `contrib/indium.yazi/` directory on `master` could not be installed;
- an `indium.yazi` branch of this repository could not be installed either;
- so the plugin needs a repository of its own.

It is [`sudo-megas/indium.yazi`](https://github.com/sudo-megas/indium.yazi) — created fresh rather
than forked, because a fork would carry this Rust tree and `ya pkg` would then copy an archive
manager's source into a plugins directory. It holds three files, which is exactly what yazi's
plugin documentation requires: `main.lua`, `README.md`, `LICENSE`.

This delivers §7's *"versioned separately"* more honestly than `contrib/` would have: its own
history, its own tags, and **INDIUM cuts no tag for it** — the P17 reasoning that it *"can never
take an INDIUM tag"* now holds by construction rather than by rule.

## Four things found by running it rather than reasoning about it

The plan for this round was written before any Lua was. Four of its statements were wrong, and
each was found by measuring.

### 1. INDIUM's own MIME list matches nothing in yazi, and fails silently

The plan specified the MIME rule from `org.indium.desktop` — `application/x-7z-compressed`,
`application/x-tar`, and the rest — on the reasoning that the plugin should preview exactly what
INDIUM opens. It matched nothing. **yazi strips the `x-` prefix before matching a rule**, and its
own built-in rules are written the same way: `application/{zip,rar,7z*,tar,gzip,…}`.

The failure mode is the dangerous part: nothing errors. The pane simply keeps showing the built-in
previewer's output, which looks exactly like the plugin failing to load. It was found only because
the built-in's output on this machine is a 7-zip error, which is conspicuous.

### 2. A preview pane does have a terminal, and an encrypted header found it

The plan said the plugin *"must never prompt — there is no terminal to prompt on inside a preview
pane"*. There is one. A preview runs as a child of yazi and inherits yazi's controlling terminal.

`cli.rs:769` asks for a password on `/dev/tty` **deliberately** — neither stdin nor stdout, so a
prompt can never land inside a pipeline or inside a file being extracted — so closing the child's
stdin changes nothing, because stdin was never where it was asking. Hovering `secret-headers.7z`
hung the pane, and every key pressed afterwards was swallowed by a prompt nobody could see.

The fix is the route INDIUM already documents: *"A cron job, a CI runner or a `setsid` child gets a
sentence and an exit code rather than a process that waits forever for a keystroke nobody is there
to type."* The plugin starts INDIUM through `setsid`, in a session of its own, and the pane shows
that sentence.

### 3. The width threshold fitted a one-character filename

The plan ruled width-adaptive rendering with the switch at 80 columns, on the basis that `--long`
spends 79 columns before the path. It does — and the path is the **last** column, so an 80-column
pane fits exactly one character of the field a listing exists for. The threshold is 96: those 79
columns plus a 17-character budget for the path, recorded in the plugin as a judgement rather than
an arithmetic.

**And 79 is not a constant.** `cli.rs:318` formats the row as
`"{:<11} {:>12} {:>12}  {:<8} {enc} {:<23} {}"`, and those are minimum widths that never truncate:
a cpio's method reads `svr4 with no crc` and takes the prefix to 87. There is no width that fits
every archive, which is why the number is a budget.

### 4. The install line the plugin's README published did not work

`ya pkg add sudo-megas/indium.yazi` fails: *"Package name `indium.yazi` must be in kebab-case"*.
`ya` appends the suffix itself, to find the repository and to name the directory it installs into.
The working line is `ya pkg add sudo-megas/indium`.

This is not a fact about this repository — `ya pkg add ndtoan96/ouch.yazi` fails identically on
`ya` 26.5.6, and that plugin is listed on yazi's own resources page. The suffixed form is stale and
printed in plenty of READMEs. It was caught because the plan's verification list required a
clean-config install *"so the README's instructions are the ones that were run"*, and running them
is the only thing that could have caught it.

## The decisions, as ruled

| | Question | Ruling |
| --- | --- | --- |
| D1 | Where the plugin lives | **Its own repository**, `sudo-megas/indium.yazi` |
| D2 | Which surface | **The preview pane** — both programs put previews on the right |
| D3 | How it renders | **Width-adaptive, and verbatim either way** |
| D4 | Release assets | **None** — INDIUM cuts no tag for it, and the plugin is installed by `ya pkg` from its default branch |
| D5 | The description | **The front page's sentence wins**, in all four places that state one |
| D6 | This round's tag | **`v1.2.0-4`** — a revision, since `Cargo.toml` does not move |

## What the plugin is

`peek` runs `indium list` over the hovered file and prints its lines; `seek` moves `skip` so a long
archive scrolls. Both are lazy: reading stops at the screenful being shown, so the first page of an
archive with a hundred thousand members costs a page.

**Nothing parses INDIUM's output.** README §4 says `--long` is *"for you to read rather than for a
script to parse"*; a preview pane is a person reading. The plugin chooses which of two commands to
run, from the width of the pane and nothing else, and prints whichever it ran unchanged — so
`--long` stays free to change shape.

Lines are clipped, never wrapped, because one line of output has to render as exactly one row or
`skip` stops counting what it says it counts. Wide panes clip the right, losing the tail of a long
path rather than every field describing it; narrow panes clip the left, because a path's useful
half is its end.

## The CORE operations

1. **§7's V1.3 entry rewritten.** It said the plugin would live *"in `contrib/`"*, which `ya pkg`
   cannot install. It now records that the gate was discharged as a measurement, where the plugin
   actually lives and why it had to, and — stated plainly, because the road table is read by people
   who have not seen the repository — that it is a plugin **for yazi**, reaching INDIUM by running
   `indium list` over the CLI shipped at V1.2. Nothing loads into INDIUM.
2. **§1 is untouched.** *"The metadata is the main event"* is the principle the program is shaped
   around, not a description of it, and the two are not in competition: being verbose about
   metadata is what having metadata as the main event looks like from outside.

## The description, in the four places that state one

`about.rs`, `Cargo.toml`, the `PKGBUILD`'s `pkgdesc`, and the `.deb`'s `Description:` synopsis —
the last lowercased and shorn of its article, because Debian policy wants a synopsis rather than a
sentence. All four move together; leaving any behind is the front-page-against-the-tree defect P19
spent a round on, and it is cheaper not to create it than to find it later.

The `.deb`'s long description needed nothing: it has always closed by saying the stated ambition is
to be one of the most verbose archiver applications in the industry.

## Deviations

1. **The plan's MIME list, threshold, tty assumption and install line were all wrong**, and all
   four are recorded above rather than quietly corrected. The pattern is one this project keeps
   paying for and keeps writing down: *a plan is a hypothesis, and the machine is the referee.*
2. **A paragraph was written into CORE §7 and removed on the maker's correction.** It argued that
   §9's *"No plugin system"* was untouched by this round. The maker's answer was that §9 is about
   INDIUM not loading plugins, and what was built is a plugin for yazi — a category error, and
   arguing against a tension that does not exist is what makes a reader believe there is one. The
   replacement states what the thing is instead of what it is not.
3. **No release assets for the plugin.** The plan's D4 said "the plugin tarball only". `ya pkg`
   installs from a default branch and never looks at releases, so a tarball would be an artefact
   nothing consumes. The repository is the distribution.

## The ritual

CORE §8.

1. **`Cargo.toml` stays `1.2.0` and `pkgrel` becomes `4`**, so `release.yml`'s derivation accepts
   only `v1.2.0-4`. Checked by running that derivation against the tree.
2. `changelog.Debian` gains a stanza whose first line is exactly
   `indium (1.2.0-4) unstable; urgency=medium`, and `RELEASE_DATE` matches that stanza's date —
   both fall on 2026-08-12, so the pin holds without moving.
3. `README.md`: the three install filenames move to `1.2.0-4`, and the two package-size badges are
   re-measured off the artefacts this tag publishes rather than carried over.
4. Commits in the house voice, from **sudo-megas**, no AI attribution anywhere.
5. Push. `ci.yml` green. Then `gh workflow run release` — the dispatch before the tag, because
   packaging is never proven on this machine.
6. Dispatch green → tag `v1.2.0-4` → tag run green → download its three artefacts →
   `gh release create v1.2.0-4`.

**The maker gave the signal.** What then happened, recorded after the fact:

- **CI failed on the first push, and the failure was the round's own miss.** `cargo fmt --check`
  is a gate that exists only in CI, and the ritual's "test" step had been read as the test suite.
  rustfmt emits the original text of any expression it cannot fit, and the old description — 23
  characters longer — was exactly long enough to make it give up on the whole `ScrollArea::show`
  closure in `about.rs`. That block had therefore been sitting one nesting level shallower than it
  belonged for as long as that sentence was there, and `--check` was green because the shallow text
  *was* rustfmt's output. The shorter sentence let it fit, it formatted the closure properly, and
  53 lines moved. **This is the second time a check that lives only in CI has been the one to
  fire.** The reformat is its own commit, because a reader looking for what the description change
  did should not have to find one line among fifty-three.
- **One block is hand-indented.** The note about addresses being selectable still overflows, so
  rustfmt still bails on it and emitted it at the depth it had before the move — which, after the
  move, is visibly wrong. Its string is re-wrapped at a different word so the literal fits, and the
  two spellings were compiled side by side and compared rather than assumed equal: Rust strips the
  newline *and* the leading whitespace after a `\`, so the sentence is unchanged.
- **The rehearsal moved a badge, and it was the closest either has come to a boundary.** The
  container Arch package measured 10,280,686 bytes — 9.8044 MiB, which a release page prints as
  **9.80** where the badge said 9.81. The residual was named before the tag rather than after:
  9.8044 would have had to *gain* about 629 bytes to round back, where P19's rehearsal-to-tag delta
  was 556 in the other direction. It gained 19. The shipped package is 10,280,705 — 9.8044,
  **9.80**. The `.deb` went the other way, 7,255,852 down to 7,253,572, and stayed at **6.92**.
- **Two releases now share a date.** `RELEASE_DATE` did not move, and P18's pin — which reads the
  changelog's newest stanza back out and compares it to what About prints — stayed green without
  being touched, which is exactly what it was put there for.
- **`v1.2.0-4` is published as Latest** with its three artefacts, sole tagger `sudo-megas`, no AI
  attribution anywhere in the round's ten commits, its tag, or its release notes.

## What this round does not do

- **No spotter.** yazi's `spot` popup is the closer analogue of the Inspector and is worth judging
  later; §7's condition was written about the preview pane, and that is what shipped.
- **No machine-readable listing.** A `--json` or field-selectable mode is the obvious ask the
  moment anything wants to parse `--long`, and it is a CLI surface decision for the maker — not
  something a plugin introduces sideways.
- **No change to INDIUM's code for the plugin's sake.** The plan said that if it started requiring
  one, the design was wrong. It required none: the plugin shells out to a binary that already does
  the work, and the only INDIUM change this round is a sentence the maker chose.
- **It does not touch the beta gate**, and it does not close any of P19's open boxes.
